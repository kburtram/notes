**Source:** `C:/repos/test/coding-docs/query-result-tabs/query_studio_vector_workbench_implementation_plan.md` (2,798 lines, dated 2026-07-10; read completely). All `:NN` refs below are line numbers in that file.

**What it is:** Implementation-ready cross-repo execution spec for a SQL Server 2025 / Azure SQL **Vector Workbench** in the Query Studio results pane. Target branches: `microsoft/sqltoolsservice@dev/query` and `microsoft/vscode-mssql@dev/query` (:5). Feature gate: **`mssql.queryStudio.vectorWorkbench.enabled`**, default off until the vertical slice passes (:7). The companion **`query_studio_vector_workbench_ux_spec.md`** is normative for visible behavior/interaction; this doc is normative for architecture, authority boundaries, data contracts, budgets, SQL generation, and implementation order (:14). The geospatial design + execution addendum establish the result-pane architecture and quality bar; their principles (ordinary STS2 result path, authoritative extension-host result store, leases + bounded secondary reads, no rows in coarse state, opaque controller-bound sessions, host-authoritative budgets, result-row identity preservation, lease release on every terminal path, compact capture fixed first, canvas as optional representation, transport/decode/semantic/interpretation separation, value-free diagnostics) remain in force (:16-29). Where the doc locks a decision, an implementation agent must not substitute a broader architecture without code-review approval (:31).

## 1. Verdict and two-layer shape (:33-53)

Proceed as a **Vector Workbench**, not a vector-only viewer. Two layers:

1. **Typed vector result foundation** (:39-44): recognize native SQL Server float32 vectors in the STS2 SqlClient driver; encode as bounded provider-neutral binary tagged cell; preserve through compact pages, RowStore, spill, snapshots, copy, export, pinned results; vector-aware result metadata/display; honest float16 driver fallback.
2. **Bounded workbench** (:46-51): analyze captured results via `IQueryResultStore` leases; heavy numerical work in an extension-host worker; only derived summaries and projection coordinates go to the webview; table-aware search/index/pipeline experiments run on an explicit isolated SQL Data Plane session; generated T-SQL + execution evidence shown for every server operation.

Flagship feature = **exact vs approximate search debugging**. PCA is included but not the thesis and not the default workspace (:53).

## 2. Locked MVP decisions (:55-107)

**Product/UI (:57-69):** conditional `Vector` sibling tab in Query Studio results; never auto-open; default workspace is `Profile`; workspaces = **Profile, Search, Compare, Projection, Index, Pipeline**; detached result analysis needs no table binding; Search/Index/most Pipeline actions require verified base-table binding; completed and terminal-partial result sets supported (live progressive analysis deferred); live Query Studio ships first, pinned parity follows in the next narrow change if unsafe to include; webview performs **zero network requests**; **no DDL executes from the pane**; **no model call without explicit confirmation**.

**Typed result support matrix (:73-79):**
- Native `VECTOR(n, float32)` via Microsoft.Data.SqlClient 6.1+ → full typed contract + detached numerical analysis.
- `VECTOR(n, float16)` (current driver/TDS fallback) → preserve as text fallback with vector metadata when provable; no automatic arbitrary-result numerical interpretation; offer controlled table-bound analysis.
- Older service/client without vector binary negotiation → prior JSON/text behavior; Vector tab limited/absent per metadata confidence.
- Arbitrary JSON array string → NOT a vector automatically (future explicit `Interpret as vector JSON` action only).
- Mixed dimensions in one expression → each cell carries its own dimensions; analysis isolates compatible groups.

**Local analysis (:81-90):** host-resolved bounded sample; heavy numerics in a Node **`worker_threads`** worker packaged as a separate extension entry point; PCA MVP = deterministic 2D, centered by default; optional L2 normalization is explicit and precedes centering; UMAP/t-SNE/3D deferred; projection rendering = local custom **Canvas 2D**; existing **Recharts** for histograms/rank charts — **no new charting dependency in MVP**; original-space distances remain authoritative.

**Database experiments (:92-99):** new isolated auxiliary **`ISqlSession`** from the same verified profile/database; exact, approximate, and forced-ANN variants run sequentially on the same diagnostic session; the session does not see local temp tables or uncommitted changes from the Query Studio session (UI must state this); structured filters only in automated comparisons; every query openable in an editor; a successful **`FORCE_ANN_ONLY`** query is direct ANN evidence — approximate syntax alone is not; plan-operator recognition is evidence-gated (no ANN claims from unapproved Showplan heuristics).

**Security/privacy (:101-106):** vector values, source text, labels, keys, distances, projection points, and model output are **result data** — never in telemetry, diagnostics, replay descriptors, capture artifacts, or production perf marks; fix full compact-row capture elision before enabling vector binary payloads; Query Studio and pinned results adopt a tested per-surface **CSP** before the Vector preview ships.

## 5. Recommended architecture (:225-270)

**Detached analysis flow (:229-248):** typed result → `SqlClientVectorValueReader` (recognize exact native vector, copy float32 components to explicit little-endian bytes, validate dimension + finite policy) → `DriverVectorValue` → `WireValueEncoder` vector tag → ordinary STS2 compact row page → `Sts2Backend` strict vector normalization → RowStore/retained snapshots → `VectorResultSource` controller adapter → sparse bounded row scan with `vectorAnalysis` reason → packed `Float32Array` sample in extension host → Node `vectorAnalysisWorker` (profile, compare, PCA, derived point chunks) → opaque pull RPC with derived data only → Vector Workbench webview.

**Table-aware flow (:249-256):** verified `VectorTableBinding` → isolated auxiliary `ISqlSession` → generated exact/approx/index/model SQL → bounded `VectorDiagnosticRunner` → result keys, distances, plans, messages, metrics → comparison/evidence model → opaque pull RPC → webview.

**Ownership boundaries (:259-270)** — key "must not own" cells: driver must not own UI summaries/PCA/SQL binding; STS2 runtime must not put `SqlVector` in public contracts; RowStore must not own parsed whole-result matrices or projection cache; the worker must not own result-store leases, VS Code APIs, or SQL sessions; `VectorDiagnosticRunner` must not touch user-query session state or hidden DDL; the pane must not own authoritative rows, a raw whole-result vector cache, or network requests.

## 6. P0 blocking prerequisites (§6, :272-358)

1. **P0 compact capture privacy (:274-288):** on `driver.queryEvent` row events, wrap the complete `compact` object (incl. `values`, `nullBitmap`, `typeHints`, future fields) before journal/digest capture; treat null patterns as result data; restore only at the existing wire/effect edge; remove side-table entries on success/suppression/error/cancel/disposal/coordinator shutdown; canaries for scalar/binary/truncated/vector-shaped/malformed both-rows-and-compact payloads; verify journal, replay export, diagnostics export, failure bundles. **Do not enable vector binary negotiation until these tests pass.**
2. **P0 shared result-cell codec (:290-305):** the vector tag must not fall through generic `{$t, v}` display logic. One dependency-light isomorphic codec used by: STS2 compact + noncompact normalization; RowStore window serialization; grid preview + tooltip; copy; text view; cell document; CSV/JSON/INSERT export; transforms + cell comparison; query-result AI/tool serialization; pinned results. No vector-only display helper in the webview.
3. **P0 provider/metadata matrix (:307-323):** live tests on every supported Windows/Linux/macOS RID vs SQL Server 2025 + Azure SQL: `GetValue`/`GetSqlValue`/`GetSqlVector<float>` CLR types; null + typed-null; `DbColumn.DataTypeName`/`DataType`/`ColumnSize`/base lineage; float32 + float16; expressions/variables/proc outputs/CTEs/views/direct columns; min/max/invalid dimensions; non-finite components; cancellation + sequential access; downgrade behavior; all-null columns; multiple vector columns/result sets. Record evidence before freezing dimension metadata rules.
4. **P0 page and frame safety (:325-344):** max float32 vector is only 7,992 raw bytes but base64+JSON expand it and pages hold hundreds. Minimum: recognize `DriverVectorValue` in byte estimation; conservative base64+wrapper overhead; **final complete UTF-8 JSON-RPC frame measurement before transport write**; stable typed row-too-large failure when one complete row cannot fit; never drop a cell/row or truncate vector components. Preferred platform fix: encode each cell/row once, pack pages from exact encoded UTF-8 sizes, keep one encoded representation through page construction + writer, advertise `pageBytesHonored` only when truthful. Exact page repacker may be a separate foundation PR; **the frame guard is non-negotiable**.
5. **P0 sparse projection (:346-350):** add general sparse projection to `CellWindowRequest` and `RowStreamRequest` before shipping label/group analysis (avoids repeated spilled-page deserialization for vector column + distant key/label/group/text/timestamp columns).
6. **P0 auxiliary session seam (:352-354):** `DocumentSessionBinding` exposes only the user session today; add a narrow diagnostic session lease; do NOT borrow the metadata session or user session.
7. **P0 Query Studio CSP (:356-358):** reusable per-surface CSP hook adopted for Query Studio + pinned results; Vector webview needs only local scripts/styles/images/fonts/canvas; no remote hosts.

## 7. STS2 typed vector contract (§7, :360-545)

**Negotiation (:362-390):** service capability `{"capabilities": {"vectorBinaryV1": true}}`; per-execute option `{"options": {"vectorEncoding": "binary-v1"}}`. Initialize advertisement states support but does not enable the new cell shape; Query Studio opts in per execute only when the gate is enabled and its codec is ready; the normalized option enters reducer/effect arguments and replay identity; non-opted-in clients keep the prior safe representation; **never emit a new tag to a client that did not opt in**.

**Provider-neutral driver value (:394-413):** C# `DriverVectorValue { int Dimensions; string BaseType /* "float32" in v1 */; string Encoding /* "f32le" */; byte[] ComponentBytes }` and `DriverVectorUnavailableValue { int? Dimensions; string? BaseType; string Reason }`. Provider CLR types stop at the SqlClient driver boundary.

**Exact recognition (:415-427):** recognize by supported SqlClient type identity — not type-name suffix, not JSON shape. Order: `reader.IsDBNull(i)` stays normal null → metadata indicates candidate vector type → `reader.GetSqlVector<float>(i)` or `GetValue(i) is SqlVector<float>` per matrix evidence → validate `IsNull`/`Length`/component memory length → copy into explicit little-endian IEEE 754 bytes. Do not expose the internal TDS `SqlVector` header; the public v1 wire payload is component bytes only.

**Little-endian encoding (:429-442):** never `MemoryMarshal.AsBytes` without an endianness contract. Explicit loop: `BitConverter.SingleToInt32Bits(vector.Memory.Span[i])` written via `BinaryPrimitives.WriteInt32LittleEndian(bytes.AsSpan(i * 4, 4), bits)` — deterministic replay + cross-platform decode.

**Wire shape (:444-507)** — success cell (verbatim keys):
```json
{ "$t": "vector", "version": 1, "status": "ok", "dimensions": 1536,
  "baseType": "float32", "encoding": "f32le", "byteLength": 6144,
  "data": "<base64 component bytes>" }
```
Unavailable cell: `{ "$t": "vector", "version": 1, "status": "unavailable", "reason": "unsupportedBaseType", "dimensions": 1536, "baseType": "float16" }`.

TypeScript (:476-506): `VectorBaseType = "float32" | "float16"`; `VectorCellOkV1`; `VectorTransportReason = "unsupportedBaseType" | "metadataMismatch" | "providerValueMismatch" | "decodeFailed" | "cellLimit"`; `VectorCellUnavailableV1`; union `VectorCellEncodingV1`.

Wire rules (:509-518): **use `data`, not `v`** (avoid collision with generic typed-scalar wrapper); `byteLength === dimensions * 4` for v1 success; base64 decoded length must equal `byteLength`; per-cell dimensions authoritative over column metadata; no duplicate JSON display string in the payload; **never truncate vector bytes — a vector is complete or unavailable**; normal null uses the existing null bitmap, not a vector status; an all-null typed column can still be eligible via metadata but detached numeric actions explain no analyzable value exists.

**Float16 policy (:520-541):** driver transmits float16 as JSON text; v1 doesn't pretend otherwise. Result path: preserve original text cell via existing bounded text handling; attach column metadata only when provider/catalog evidence proves vector float16; transport mode `textFallback`; grid/export keep JSON; detached numeric analysis disabled by default; offer table binding. Table-bound float16 analysis: query catalog dims/base type; explicit bounded diagnostic `CAST(vector_column AS nvarchar(max))` or Phase-0-proven provider fallback; parse strict numeric JSON array; require exact dimension match; promote to float32 for local analysis only; label every result `Source float16, analyzed as float32 after JSON conversion`; use the native server column (not the promoted copy) for search experiments.

**Compact type hint (:543-545):** explicit column-aligned hint `vector:f32le:v1`; permits fast routing/compat checks but never trusted without structural validation (tag remains self-describing).

**Grid operations (:597-604):** disable scalar ordering on typed vector cells (SQL vectors have no comparison ordering); grid filtering = null/not-null (maybe status), not lexical JSON comparison; exact vector equality exists only inside the Workbench and uses byte equality for float32 typed cells; generic transform predicates treat vector cells as opaque/incomparable; RowStore spill preserves the tag unchanged.

**Decode API (:607-627):** `DecodedFloat32Vector { dimensions; values: Float32Array }`; `decodeVectorFloat32(cell)`; `decodeVectorPrefix(cell, maxComponents): number[]`; `vectorCellSummary(cell): VectorCellSummary`. ## 11. Controller-bound analysis sessions and RPC (§11, :727-854)

**Authority rule (:731-735):** webview sends result-set + column selections only — never store/run/snapshot/source ID, lease owner, or budget. Query Studio controller binds to its current `RetainedRowStore`; pinned controller binds to its owned snapshot; each opens a lease internally.

**Session state machine (:738-748):** `open -> scanning -> computing -> streamingDerived -> completed | cancelled | expired | failed`. Normal completion removes the session and releases the store lease immediately.

**Operations (:753-760):** `VectorAnalysisOperation = VectorProfileOperation | VectorProjectionOperation | VectorCompareOperation | VectorSelectionProfileOperation`. Do NOT build a universal visualization-operation framework — this union belongs to the Vector feature.

**Open contract (:765-803):** `QsVectorAnalysisOpenParams { resultSetId, vectorColumn, labelColumn?, groupColumn?, keyColumns?, operation }` → `QsVectorAnalysisOpenResult { handle: string; generation: string; frozen: { resultSetId, rowCount, complete, truncatedReason?, corrupt, vectorColumn, dimensions?, baseType? }; effectiveBudget: QsVectorEffectiveBudget }`. `QsVectorEffectiveBudget = { maxRowsScanned, maxSampleRows, maxComponents, maxInputBytes, maxDerivedBytes, maxEvalMs, targetResponseBytes, maxResponseBytes }`. Host resolves budgets from the query-results parameter registry; **webview requests cannot raise them** (:802).

**Pull protocol (:807-829):** `QsVectorAnalysisNextParams { handle, generation, sequence }` → `QsVectorAnalysisChunk { handle, generation, sequence, events, payloadBytes, done }` where `QsVectorAnalysisEvent` kinds = `"progress" | "profile" | "projectionPoints" | "projectionSummary" | "compare" | "terminal"`. Rules (:831-841): at most one `next` in flight per handle; strictly monotonic sequences; manager buffers at most one bounded derived chunk per operation; the next request is the consumption/backpressure boundary; `cancel` idempotent; expiry/rerun/panel-hide/disposal/selection-column-change/final-completion release lease + worker; use **`webviewPanel.visible`** (not only active) for host-side hidden cleanup; inactive-but-visible split panels stay alive under global caps; counts scoped to scanned/sample rows until a complete full scan is proven.

**Row identity (:843-854):** `VectorResultIdentity { resultRowOrdinal: number; originRowOrdinal?: number }`; `originRowOrdinal` only when a derived source explicitly provides lineage — never invented.

## 12. Sampling (§12, :856-894)

Default = **deterministic uniform-window sampling** (not naive prefix, not silent reservoir — reservoir can force full scan of millions of spilled rows; windows give a predictable I/O cap, :880-881). Strategy (:863-877): effective cap = min(configured max sample rows, `floor(maxComponents / dimensions)`, `floor(maxInputBytes / (dimensions * 4))`, total rows); ≤32 windows; proportional row allocation; deterministic seed derived from store run ID + result set ID + vector column + operation-spec digest + fixed algorithm version; read windows in source-row order via sparse projection; exclude null/unavailable/mismatched cells with reason counts; no unbounded replacement reads (bounded disclosed oversample factor allowed). User-requested full profile scans sequentially under the larger full-scan budget (:878).

`VectorSampleDescriptor { method: "full" | "uniformWindows" | "selection" | "prefix"; seed?; sourceRows; rowsScanned; vectorsAccepted; vectorsRejected; completeSourceScan; windows? }` (:885-894).

## 14. Numerical algorithms (§14, :954-1125)

**Common validation (:958-967):** dimension matches active compatible group; exact float32 decode; non-finite components counted and excluded where unsupported; no normalization unless the operation says so; **float64 accumulation** for sums/means/variance/norms/dots/distances; float32 OK for render-precision outputs.

**Norms (:969-978):** L1/L2/L-infinity; scaled sum-of-squares for L2 to reduce overflow/underflow; compare vs server `VECTOR_NORM` fixtures.

**Distances (:980-996)** must match SQL labeling: `cosine distance = 1 - dot(a,b)/(norm2(a)*norm2(b))`; `euclidean = sqrt(sum((a_i-b_i)^2))`; `negative dot product = -sum(a_i*b_i)`. Zero-norm cosine: mark undefined (never coerce to 0 or 1), count and display affected pairs. Compensated/pairwise summation where benchmarks justify; tolerances tested vs SQL Server outputs.

**Component statistics (:998-1009):** Welford/Chan per dimension (count, mean, M2, min, max, non-finite count); arrays are O(dimensions).

**Exact duplicates (:1011-1023):** hash raw component bytes (SHA-256 or faster noncrypto hash + byte verification); never log the hash; groups require final byte comparison; report exact binary duplicates only. Table-bound float16: label `Exact after JSON conversion to float32`.

**Near-zero (:1025-1031):** exact zero (every component bit numerically zero, +0/-0 by numeric comparison) reported separately from near zero (L2 ≤ threshold, default **`1e-6`**, adjustable, part of the result); near-zero vectors are not "invalid".

**Centroid/outliers (:1033-1044):** centroid = component-wise mean over accepted sample; default outlier score = selected-metric distance from centroid; zero-norm rows separated for cosine; top-N + median + robust percentile threshold; no universal "bad" label; robust medoid/local density deferred.

**Pair-distance distribution (:1046-1052):** deterministic random pairs without replacement; cap default 10,000; operation seed; report pair count + metric; group comparison samples within-group and between-group separately.

**Pairwise matrix (:1054-1060):** soft cap 100 selected vectors, hard cap 200; O(n²·d) cost shown before running above the soft cap; compute upper triangle + mirror; stream matrix rows if payload approaches RPC limits.

**PCA 2D (:1062-1110):** preprocessing = optional explicit row L2 normalization → float64 component means → center. Required output: PC1/PC2 score per accepted row; component vectors or digest/version; eigenvalues/variance PC1+PC2; total sampled variance; explained-variance %; sample descriptor; algorithm version + iteration count; convergence status. Algorithm = **covariance-free orthogonal iteration** with a `dimensions x 3` deterministic random matrix: orthonormalize via modified Gram-Schmidt + reorthogonalization; 6–10 bounded iterations of `Z = X*Q`, `Y = X^T*Z`, orthonormalize Y → new Q, subspace-convergence test; form 3×3 projected covariance `B = (XQ)^T(XQ)/(n-1)`; bounded Jacobi eigendecomposition; rotate Q, sort by descending eigenvalue, keep 2; scores = `X * Q2`. Three working components for a 2-component output: better separation when λ2≈λ3, convergence check, still bounded (:1096-1100). Correctness: deterministic per (sample, seed, options, algorithm version); deterministic sign normalization (largest absolute loading positive); scores vs NumPy fixtures up to sign/rotation tolerance; **no explicit d×d covariance matrix**; cancellation between matrix passes; time budget yields honest partial/no-result terminal, never a half-projection (:1102-1110).

**Projection point payload (:1114-1124):** `VectorProjectionPoint { resultRowOrdinal; x; y; label?; group?; numericColor? }` — **no vector components in webview point payloads**.
